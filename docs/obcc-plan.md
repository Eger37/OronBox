## 一、Creator Center 的整体定位

Creator Center 是资源创作者的工作台，核心任务只有三类：

```text
查看自己的资源
编辑和提交资源
查看审核状态并继续处理
```

它不是资源社区，也不是消息中心，也不是后台管理系统。

资源评论、点赞、收藏等互动继续留在主 App 的资源详情页。消息箱只负责通知和跳转。审核页面只处理创作者自己的审核过程，不能变成审核员后台。

整个 Creator Center 使用主 App 的移动 MD3 壳，不复制 ABCC 的桌面双栏布局。

顶级导航固定为：

```text
概览｜资源｜审核｜管理（仅管理员）
```

不设置“设置”Tab。Creator Center 不需要单独的设置页。

---

## 二、Creator Center 根页面

路由：

```text
/resources/creator
```

根页面顶部是固定的 Creator Center 顶栏：

```text
[返回] 创作者中心                         [刷新] [铃铛]
```

交互：

- 点击返回：
  - 弹出“退出创作者中心”
  - 文案是“确定要退出创作者中心吗？”
  - 取消：留在 Creator Center
  - 确认：返回上一级
- 点击刷新：
  - 刷新资源、账号状态、授权状态、待处理审核状态
- 点击铃铛：
  - 跳转主 App 消息箱
  - Creator Center 不承载消息列表

底部使用主 App 的 `NavigationBar`：

```text
概览｜资源｜审核｜管理
```

管理员判断来自现有账号角色/权限数据。普通创作者完全不显示“管理”。

---

## 三、概览页

路由：

```text
/resources/creator
```

概览页不是资源列表，也不是发布目标设置页。它只汇总当前创作者已经存在的数据和状态。

页面顺序固定为：

### 1. GitHub

普通 item：

```text
GitHub
username / 未连接
```

GitHub 在这里代表 AstroBox Repo 使用的 GitHub 基础设施。

它不应该被设计成独立的“AstroBox 账号”或“同步平台”。

交互：

- 已连接：
  - 显示 GitHub 用户名
  - 可以进入授权状态或重新授权
- 未连接：
  - 点击进入 GitHub OAuth
  - 授权完成后刷新 Creator Workspace
- 缺少必要 scope：
  - 显示授权失败原因
  - 引导重新授权
- 不在概览里展开仓库、PR、评论详情

### 2. 米坛社区

普通 item：

```text
米坛社区
username / 未连接
```

交互：

- 已登录：显示账号名
- 未登录：点击进入米坛授权
- 授权状态只表示米坛发布能力是否可用
- 米坛每日发布限制不能伪造剩余次数
- 限制失败由已有发布错误流程处理

### 3. 待处理事项

只展示现有数据中需要创作者处理的状态：

```text
需要修改
等待审核
发布失败
```

每一项都是可点击的状态入口：

- “需要修改”跳转审核列表，并预选对应状态
- “等待审核”跳转审核列表
- “发布失败”跳转资源页或对应资源编辑页

这里不增加：

```text
最近活动
发布权限
同步可用
已暂停
目标状态摘要
历史发布记录
```

### 4. 资源状态概览

只使用已有资源状态：

```text
草稿
待审核
已通过
已拒绝
发布失败
已发布
```

每个状态是统计或入口，不创建新的状态模型。

概览页不重新发明资源状态，也不把 GitHub/米坛状态拆成独立“发布权限”卡片。

## 四、资源页

路由：

```text
/resources/creator/resources
```

资源页基本复用当前已有资源列表，不重新设计一套资源卡片。

复用内容包括：

- `CreatorResourceList`
- 现有资源 item
- 现有状态 badge
- Chip 筛选
- 刷新
- 空状态
- 加载状态
- 合集
- 多选
- 移动到合集
- 新建资源入口

顶部结构应与主 App 资源列表一致：

```text
顶栏
标题/操作
Chip 筛选
资源列表
```

筛选使用横向 Chip，不使用下拉菜单。

资源 item 点击后进入资源编辑页：

```text
/resources/creator/resources/:resourceId
```

资源编辑页必须可以通过资源 ID 独立恢复，不能依赖“之前是否在 controller 里选中过资源”。

---

## 五、新建资源页

路由：

```text
/resources/creator/resources/create
```

新建资源继续复用现有创建流程。

交互：

1. 选择资源类型：
   - 快应用
   - 表盘
2. 填写最基本的名称、简介等信息
3. 创建服务端资源
4. 创建成功后进入资源编辑页：

```text
/resources/creator/resources/:resourceId
```

不能创建完成后只依赖内存中的 selected workspace。

---

## 六、资源编辑页

资源编辑页不是线性向导，而是“三段式自由切换编辑器”。

路由：

```text
/resources/creator/resources/:resourceId
```

顶部内容区域：

```text
编辑信息｜文件绑定｜发布配置
```

三个阶段都可以直接点击切换。切换不自动提交、不强制校验上一段、不改变现有保存逻辑。

底栏复用现有 `CreatorBottomBar`。

按钮规则：

```text
编辑信息：下一步
文件绑定：下一步
发布配置：提交
```

这里的“下一步”只是切换到下一个阶段，不是线性流程控制。

---

## 七、编辑信息阶段

内容顺序：

```text
基本信息
附加链接
图标与封面
预览图
```

### 基本信息

复用当前字段：

- 名称
- 简介
- 类型
- 付费类型
- 版本相关信息

### 附加链接

复用现有链接编辑器。

链接属于资源信息，不属于某一个发布平台。

保存后需要通过服务端 revision/publication 流程传递到：

- OronBox
- AstroBox manifest 的 links 数组
- 米坛正文开头的链接区块

### 图标与封面

复用现有媒体卡片：

- 图标
- 封面

不改变现有媒体上传、压缩、校验逻辑。

### 预览图

复用现有预览图列表：

- 上传
- 删除
- 排序
- 校验尺寸和格式

---

## 八、文件绑定阶段

内容顺序：

```text
资源文件
外部购买
```

### 资源文件

复用现有 artifact 卡片和分析流程：

- 上传资源包
- 下载资源包
- 分析资源包
- 查看分析结果
- 绑定设备
- 显示包名
- 显示表盘 ID
- 显示版本
- 显示文件大小
- 显示设备绑定

上传前 gate：

快应用：

```text
快应用识别失败：快应用缺少包名，无法上传
```

默认 VelaJS 包名：

```text
识别到快应用包名为 com.application.watch.demo，这是 VelaJS 项目默认包名，请先修改后再上传
```

表盘：

```text
表盘识别失败或全零：表盘缺少 ID，无法上传
```

资源识别器负责提供包名/表盘 ID，编辑器不自己猜测。

表盘全零 ID 的输入对话框：

```text
识别到表盘 ID 为全零，请修改后上传
```

包含：

- 输入框
- 提示语
- 取消
- 确认

确认时必须校验新 ID 格式。确认后由客户端将修改应用到文件，再继续上传。

### 设备过滤

设备支持由服务端目录与发布目标映射决定，不硬编码 8 Pro 或 S1 Pro。

BandBBS：

- 没有对应分区 ID 的设备不发布
- 提交块下显示：

```text
跳过发布
[图标] 设备 A
[图标] 设备 B
```

设备名左对齐，纵向分行，使用一个信息块，不拆成多个卡片。

AstroBox：

- 没有对应 AstroBox device ID 的设备不写入 manifest 支持声明
- 提交块下显示：

```text
过滤支持
[漏斗图标] 设备 A
[漏斗图标] 设备 B
```

创作者勾选同步发布时，SnackBar 只做模糊提示，不列具体设备名：

```text
勾选的部分支持设备暂不支持同步发布到米坛社区，将会跳过这部分设备的发布
```

或：

```text
勾选的部分支持设备暂不支持同步发布到 AstroBox，将会过滤这部分设备的支持声明
```

具体设备名只出现在发布配置页面的信息块中。

### 外部购买

复用现有购买信息编辑：

- 商品链接
- 金额
- 购买说明

不把它拆成新的发布目标。

---

## 九、发布配置阶段

内容顺序严格为：

```text
审核状态
发布目标
```

审核状态必须放在发布配置内容顶部，不能塞到顶栏，也不能放在页面底部。

### 审核状态

展示现有审核反馈：

- 当前资源审核状态
- 审核备注
- 治理提示
- 当前 revision 状态
- 必要时的审核时间

不新增：

```text
详细发布状态
已有发布记录
历史发布记录
讨论区
```

“已有发布记录”如果只是历史信息，不放进这里。

### 发布目标

继续复用现有发布目标编辑器：

```text
OronBox
BandBBS
AstroBox-Repo
```

GitHub 仓库、分支、PR 是 AstroBox Repo 的基础设施，不是第四个发布目标。

发布目标卡片负责：

- 是否启用目标
- 目标授权状态
- 目标绑定信息
- 设备映射结果
- 目标特有校验
- 支持/跳过/过滤提示

---

## 十、底栏和提交交互

底栏始终复用现有实现：

编辑信息：

```text
删除 / 保存草稿 / 下一步
```

文件绑定：

```text
删除 / 保存草稿 / 下一步
```

发布配置：

```text
删除 / 保存草稿 / 提交
```

提交前执行现有校验：

- 名称和简介
- 资源文件
- 包名/表盘 ID
- 设备绑定
- 媒体
- 目标授权
- BandBBS 分区映射
- AstroBox GitHub 授权
- 购买信息

提交不是在三个阶段间切换时触发的。

## 十一、审核列表页

路由：

```text
/resources/creator/reviews
```

审核列表不是消息列表，也不是资源列表。它展示的是 review case：

```text
一次资源 revision 对应的一次审核过程
```

页面顶部与资源列表一致：

```text
顶栏
标题
横向 FilterChip
审核案列表
```

Chip 固定为：

```text
全部
等待审核
需要修改
已修复待复核
已通过
已拒绝
已关闭
```

服务端只负责：

- 当前用户归属过滤
- 全部审核案返回
- cursor 分页
- 稳定排序

客户端负责：

- 合并分页
- 去重
- 本地 Chip 筛选
- 滚动加载更多

审核案 item：

```text
资源图标
资源名称
普通审核 / AstroBox 审核
当前状态
更新时间
```

点击后进入独立审核状态页：

```text
/resources/creator/reviews/:reviewCaseId
```

---

## 十二、普通审核状态页

路由：

```text
/resources/creator/reviews/:reviewCaseId
```

使用主 App MD3 单列布局：

```text
[返回] 审核状态                         [刷新]

资源摘要 Card
审核状态 Card
审核备注
提交时间
更新时间
页面操作
```

普通审核案不显示任何 AstroBox 内容：

- 不显示 GitHub PR
- 不显示评论时间线
- 不显示 PR 标签
- 不显示追加修改
- 不显示 GitHub 链接

普通审核状态：

- 通过
- 打回
- 等待审核
- 其他已有状态

通过就结束，打回就回到资源编辑页处理。不能强行套 AstroBox 的对话式审核流程。

---

## 十三、AstroBox 审核状态页

只有该审核案存在 AstroBox publication target 时，才显示 AstroBox 专属内容。

页面仍然是主 App 的单列 MD3，不使用 ABCC 的桌面双栏布局。

内容顺序：

```text
资源摘要
AstroBox 审核状态
PR 摘要
变更摘要
审核评论时间线
创作者操作
```

PR 摘要包括：

- 仓库
- PR 编号
- open/closed 状态
- 更新时间
- changed files
- 打开 GitHub 原始 PR

评论时间线包括：

- 审核 comment
- 创作者补充说明
- 时间
- 作者
- 编辑状态
- 删除状态

每条评论操作：

- 回复
- 编辑自己的评论
- 删除自己的评论
- 打开 GitHub 原评论
- 定位 `回复 #编号`

这里的“回复”必须和具体 comment 建立上下文关系，不能只是一个没有关联的普通新评论。

---

## 十四、AstroBox 追加修改

只有同时满足以下条件才显示“修改资源”入口：

```text
审核案是 AstroBox 类型
存在需要处理的审核 comment
当前 PR 仍可更新
```

点击修改资源后进入同一个资源编辑器，不复制另一套编辑页面。

资源修改完成后，在“发布配置”点击提交，弹窗：

```text
应用修改

☑ GitHub 仓库与 PR
☑ OronBox

☐ 米坛社区

取消        确认
```

规则：

- GitHub 仓库与 PR 默认勾选
- OronBox 默认勾选
- 米坛默认不勾选
- 普通审核案不显示此弹窗
- AstroBox 修正不能自动新增米坛提交
- 米坛只有创作者主动勾选才提交

---

## 十五、消息箱关系

消息箱继续使用主 App 的统一消息箱，不迁移到 Creator Center。

深链规则：

```text
审核消息
→ /resources/creator/reviews/:reviewCaseId

资源评论消息
→ /resources/detail/:resourceId?comment=:commentId
```

消息箱只负责：

- 展示通知
- 标记已读
- 跳转目标页面

资源互动继续在资源详情页：

- 评论
- 回复
- 点赞
- 举报
- 其他资源 UGC

Creator Center 不增加“讨论”Tab，也不增加资源评论区。

---

## 十六、管理 Tab

管理 Tab 是唯一的权限条件页面。

普通创作者：

```text
概览｜资源｜审核
```

管理员：

```text
概览｜资源｜审核｜管理
```

管理 Tab 不改变创作者资源发布流程，也不把审核员功能混进创作者审核状态页。

如果当前管理页面能力尚未明确，至少必须：

- 权限条件准确
- 路由独立
- 普通用户不可见、不可进入
- 不伪造尚不存在的管理功能
